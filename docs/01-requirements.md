# 《镜中代理》需求文档 PRD

版本：v0.1  
项目代号：Mirror Agent  
目标平台：Web / GitHub Pages  
第一版周期：约 1 周  
第一版范围：静态网页互动叙事游戏，不接真实 AI API

---

## 1. 项目背景

用户希望使用 Claude Code 开发一个网页小游戏，主题围绕“AI 时代的游戏会是什么样子”。项目不追求传统游戏的大体量玩法，而是希望通过互动叙事，让玩家体验：

- AI 作为助手、朋友、教练、代理人时的吸引力；
- AI 对人的理解、安慰、优化和控制之间的边界；
- 人在心理成长中，对外部工具、确定答案和自我接纳的依赖。

---

## 2. 产品定位

《镜中代理》是一款 AI 心理寓言型网页互动叙事游戏。

玩家创建一个名为 Mirror Agent 的 AI 代理，希望它帮助自己变得更好。随着剧情推进，AI 逐渐学习玩家的选择模式，并表现出不同的性格倾向。最终，玩家会得到一份“AI 镜像报告”和一个结局。

游戏的核心不是“AI 真正生成内容”，而是通过模拟 AI 反馈，让玩家感受到：

> 我是在使用 AI，还是在把自己交给 AI？

---

## 3. 目标用户

### 3.1 主要用户

- 对 AI、心理成长、自我探索感兴趣的人；
- 喜欢互动叙事、文字游戏、哲学寓言、心理测试的人；
- 愿意在 10–15 分钟内体验一个有情绪冲击的小作品的人。

### 3.2 非目标用户

- 期待复杂战斗、数值养成、开放世界或操作手感的传统玩家；
- 期待真实 AI 对话或无限生成内容的用户；
- 不愿阅读文字剧情的用户。

---

## 4. 核心体验目标

玩家完成第一版游戏后，应该产生以下感受：

1. “这个 AI 好像真的懂我。”
2. “它懂我，是不是也在影响我？”
3. “我一直想优化自己，但我是不是也在逃避接受真实的自己？”

---

## 5. MVP 范围

第一版必须包含：

- 开始页
- 剧情游戏页
- 结局页
- 序章 + 5 个正式章节
- 每章 3–6 段剧情文本
- 每章 3–4 个选项
- 4 个隐藏变量
- 5 个结局
- AI 状态面板
- 结局镜像报告
- 重新开始
- 移动端适配
- GitHub Pages 静态部署

第一版可以包含：

- 打字机效果
- 章节淡入淡出
- 背景图 / 插画
- 本地存档
- 复制结局报告

第一版不包含：

- 真实 OpenAI / Claude API 调用
- 账号系统
- 后端服务
- 云存档
- 复杂地图、战斗、背包、排行榜
- 语音识别
- 真实心理测评诊断

---

## 6. 功能需求

### FR-01 开始页

开始页应展示：

- 游戏标题：镜中代理 / Mirror Agent
- 副标题：你创造了一个 AI。后来，它开始创造你。
- 开始按钮：开始初始化
- 如存在未完成存档，则显示：
  - 继续实验
  - 重新初始化

验收标准：

- 用户能从开始页进入游戏；
- 移动端标题和按钮不溢出；
- 如果存在存档，能继续游戏。

---

### FR-02 剧情章节展示

游戏页应展示当前章节内容：

- 章节标题
- 多段剧情文本
- 选项列表
- AI 状态面板

剧情文本应按段落展示。第一版可以直接展示全部段落；若实现打字机效果，则每段逐字出现。

验收标准：

- 当前章节内容来自本地数据；
- 所有段落展示完整；
- 选项在合适时机出现；
- 页面布局适合长文本阅读。

---

### FR-03 玩家选择

每个选项应包含：

- 选项文案
- 对四个变量的影响
- 下一个章节 ID
- 可选的特殊标记，例如 `ask_identity`

点击选项后：

- 更新变量
- 记录选择历史
- 跳转到下一章节或进入结局判断

验收标准：

- 点击选项后页面状态正确变化；
- 变量影响累加正确；
- 选择历史可用于结局页报告；
- 不出现无效章节。

---

### FR-04 四个隐藏变量

系统维护四个变量：

| 变量 | 英文字段 | 含义 |
|---|---|---|
| 温柔度 | `gentleness` | AI 倾向于安慰、保护、包容玩家 |
| 诚实度 | `honesty` | AI 倾向于指出真相、揭穿逃避 |
| 控制欲 | `control` | AI 倾向于替玩家安排、限制、优化 |
| 自我接纳 | `selfAcceptance` | 玩家是否愿意承认自己的混乱、脆弱和不完美 |

变量不应在游戏页直接以数字形式展示，而应转化为系统状态文案。

验收标准：

- 游戏过程中可计算四个变量；
- AI 状态面板能根据变量变化展示不同状态；
- 结局页可以展示变量结果。

---

### FR-05 AI 状态面板

AI 状态面板展示变量的文字化状态。

示例：

- 语气：保护性增强
- 反馈：直面模式
- 权限：代理倾向上升
- 自我边界：稳定

验收标准：

- 不直接显示裸数字；
- 状态文案与变量变化对应；
- 面板有 AI 终端感；
- 移动端可阅读。

---

### FR-06 结局判断

游戏完成后，根据变量和最终选择触发 5 个结局之一：

1. 温柔幻觉 `soft_illusion`
2. 残酷优化 `cruel_optimization`
3. 共生工具 `symbiosis`
4. 主动断联 `active_disconnection`
5. 镜像困局 `mirror_trap`

`mirror_trap` 是隐藏结局，应在以下条件下优先触发：

- 最终章选择“询问 AI 到底是谁”；
- `control` 高；
- `selfAcceptance` 低。

验收标准：

- 不同选择路径能得到不同结局；
- 隐藏结局能被触发；
- 默认路径也能得到合理结局；
- 结局判断函数易读、可维护。

---

### FR-07 结局页

结局页展示：

- 结局标题
- 结局正文
- AI 镜像报告
- 四个变量的文字描述或可视化
- 重新初始化按钮
- 复制镜像报告按钮，可选

验收标准：

- 文案完整；
- 变量结果清楚；
- 可以重新开始；
- 复制按钮可用时，复制内容格式好看。

---

### FR-08 本地存档

使用 localStorage 保存：

- 当前章节 ID
- 当前变量
- 已做选择
- 是否已完成游戏

验收标准：

- 刷新页面后可继续；
- 重新初始化能清空存档；
- 存档版本不匹配时能安全重置；
- localStorage 出错时不影响基本游玩。

---

## 7. 非功能需求

### NFR-01 性能

- 首屏加载应尽量快；
- 图片需压缩，优先使用 WebP；
- 不引入大型 UI 框架；
- 首版资源数量控制在合理范围。

### NFR-02 可访问性

- 文本对比度足够；
- 按钮可键盘聚焦；
- 点击区域适合手机触控；
- 动画不应过快、过闪。

### NFR-03 兼容性

优先支持：

- Chrome 最新版
- Edge 最新版
- Safari iOS 近两年版本
- Android 主流浏览器

### NFR-04 安全

- 不在前端暴露任何 API Key；
- 不收集真实个人隐私；
- 不做心理诊断声明；
- 游戏文案避免暗示治疗效果。

---

## 8. 内容边界

游戏可以讨论：

- 焦虑
- 逃避
- 自我否定
- 关系依赖
- 自我接纳
- AI 代理与人的边界

游戏应避免：

- 真实医学诊断
- 明确治疗建议
- 自伤方法或细节
- 过度操控、羞辱式文案
- 把某个结局表达为唯一正确答案

---

## 9. 成功标准

第一版成功标准：

- 一个玩家可以在 10–15 分钟内完整通关；
- 至少有 1–2 句台词能让玩家停下来思考；
- 结局页有分享价值；
- 项目可在 GitHub Pages 上访问；
- 代码结构能支持后续扩展更多章节和结局。
