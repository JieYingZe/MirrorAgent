# 《镜中代理》需求文档 PRD

版本：v0.1  
项目代号：Mirror Agent  
目标平台：Web / GitHub Pages  
第一版周期：约 1 周  
第一版范围：静态网页互动叙事游戏，不接真实 AI API

更新：2026-07-28 完成一次文档一致性整理，与仓库实际结构对齐。

---

## 1. 项目背景

用户希望使用 Claude Code 开发一个网页小游戏，主题围绕“AI 时代的游戏会是什么样子”。项目不追求传统游戏的大体量玩法，而是希望通过互动叙事，让玩家体验：

- AI 作为助手、朋友、教练、代理人时的吸引力；
- AI 对人的理解、安慰、优化和控制之间的边界；
- 人在心理成长中，对外部工具、确定答案和自我接纳的依赖。

---

## 2. 产品定位

《镜中代理》是一款 AI 心理寓言型网页互动叙事游戏。

玩家创建一个名为 Mirror Agent 的 AI 代理，希望它帮助自己变得更好。随着剧情推进，AI 逐渐学习玩家的选择模式，并表现出不同的性格倾向。最终，玩家会得到一份“AI 镜像报告”和一个结局。

游戏的核心不是“AI 真正生成内容”，而是通过模拟 AI 反馈，让玩家感受到：

> 我是在使用 AI，还是在把自己交给 AI？

---

## 3. 目标用户

### 3.1 主要用户

- 对 AI、心理成长、自我探索感兴趣的人；
- 喜欢互动叙事、文字游戏、哲学寓言、心理测试的人；
- 愿意在 10–15 分钟内体验一个有情绪冲击的小作品的人。

### 3.2 非目标用户

- 期待复杂战斗、数值养成、开放世界或操作手感的传统玩家；
- 期待真实 AI 对话或无限生成内容的用户；
- 不愿阅读文字剧情的用户。

---

## 4. 核心体验目标

玩家完成第一版游戏后，应该产生以下感受：

1. “这个 AI 好像真的懂我。”
2. “它懂我，是不是也在影响我？”
3. “我一直想优化自己，但我是不是也在逃避接受真实的自己？”

---

## 5. MVP 范围

第一版必须包含（P0，缺少任何一项都无法通关）：

- 开始页
- 剧情游戏页
- 结局页
- 序章 + 5 个正式章节
- 每个剧情节点 3–6 段文本，每个选择节点 3–4 个选项，一章包含多个选择节点
- 4 个隐藏变量
- 6 个结局家族，11 个玩家可见结局
- AI 状态面板
- 结局镜像报告
- 重新开始
- 移动端适配
- GitHub Pages 静态部署

第一版应当包含（P1，不阻塞通关，但属于第一版目标）：

- 打字机效果
- 章节淡入淡出
- 背景图 / 插画
- 本地存档
- 启动遮罩（StartupGate）
- BGM 场景映射与切换
- 全局静音／恢复声音控制

第一版可以包含（P2，时间不足时可延后）：

- 普通交互音效（SFX）
- 复制结局报告
- 选择路径摘要

第一版不包含：

- 真实 OpenAI / Claude API 调用
- 账号系统
- 后端服务
- 云存档
- 复杂地图、战斗、背包、排行榜
- 语音识别
- 真实心理测评诊断

## 6. 功能需求

### FR-00 启动遮罩 StartupGate

优先级：P1。

浏览器会阻止未经用户交互的有声自动播放，因此第一版采用启动遮罩方案：打开网页后先显示一层轻量覆盖层，用户点击「点击进入实验」后再尝试解锁音频并进入 StartPage。

启动遮罩是应用级覆盖层，不是第四个核心业务页面，不承担任何剧情或存档职责。

完整流程见 `docs/03-interaction-design.md` §2。

验收标准：

- 打开网页后先显示启动遮罩，而不是直接显示 StartPage；
- 点击「点击进入实验」后进入 StartPage；
- 音频解锁或播放失败时仍然进入 StartPage，不阻塞，也不弹出错误弹窗；
- 「点击进入实验」与「开始初始化」是两个独立动作，不合并。

---

### FR-01 开始页

开始页应展示：

- 游戏标题：镜中代理 / Mirror Agent
- 副标题：你创造了一个 AI。后来，它开始创造你。
- 开始按钮：开始初始化
- 如存在未完成存档，则显示：
  - 继续实验
  - 重新初始化

验收标准：

- 用户能从开始页进入游戏；
- 移动端标题和按钮不溢出；
- 如果存在存档，能继续游戏。

---

### FR-02 剧情展示

一个视觉章节由多个剧情节点组成。游戏页应展示当前节点的内容：

- 章节标题
- 多段剧情文本（旁白、对话、系统日志、记录、消息、文件等）
- 选项列表或“继续”按钮
- AI 状态面板

剧情文本应按块展示。第一版可以直接展示全部内容；若实现打字机效果，则逐字出现。

验收标准：

- 当前内容来自本地数据；
- 所有内容展示完整；
- 选项在合适时机出现；
- 页面布局适合长文本阅读；
- 页面顶部显示视觉章节标题，而不是节点 ID。

---

### FR-03 玩家选择

每个选项应包含：

- 选项文案
- 选择类型（roleplay / exploration / key / final）
- 对四个变量的影响
- 下一个节点（可为条件路由）
- 可选的选项专属回应
- `final` 类型的选择需写入 `finalChoice`（`permanent_agent` / `tool_only` / `close_agent`），并且不修改四变量

点击选项后：

- 更新变量、tags、flags
- 记录选择历史
- 显示选项专属回应（如有）
- 跳转到下一节点或进入结局判断

验收标准：

- 点击选项后页面状态正确变化；
- 变量影响累加正确；
- 选择历史可用于结局页报告；
- 不出现无效节点。

---

### FR-04 四个隐藏变量

系统维护四个变量：

| 变量 | 英文字段 | 含义 |
|---|---|---|
| 温柔度 | `gentleness` | AI 倾向于安慰、保护、包容玩家 |
| 诚实度 | `honesty` | AI 倾向于指出真相、揭穿逃避 |
| 控制欲 | `control` | AI 倾向于替玩家安排、限制、优化 |
| 自我接纳 | `selfAcceptance` | 玩家是否愿意承认自己的混乱、脆弱和不完美 |

变量不应在游戏页直接以数字形式展示，而应转化为系统状态文案。

验收标准：

- 游戏过程中可计算四个变量；
- AI 状态面板能根据变量变化展示不同状态；
- 结局页可以展示变量结果。

---

### FR-05 AI 状态面板

AI 状态面板展示变量的文字化状态。

示例：

- 语气：保护增强
- 反馈：直面模式
- 权限：代理预备
- 边界：清晰稳定

标签与状态文案都收得很短（标签最多两字、状态四字以内），
面板右列才对得齐；桌面端每行另有图标与英文副标，移动端隐藏。

验收标准：

- 不直接显示裸数字；
- 状态文案与变量变化对应；
- 面板有 AI 终端感；
- 移动端可阅读。

---

### FR-06 结局判断

判断原则：

```txt
最终行为决定「玩家最后做了什么」。
此前累计的四变量、强授权记录与边界收回记录
决定「这个行为最终意味着什么」。
```

三个真正的最终行为（`permanent_agent` / `tool_only` / `close_agent`）本身不修改四变量。

游戏完成后触发 11 个玩家可见结局之一，分属 6 个结局家族：

| 家族 | 玩家可见结局 |
|---|---|
| `mirror_trap` | 镜像困局（隐藏） |
| `soft_illusion` | 温柔幻觉 |
| `cruel_optimization` | 残酷优化 |
| `silent_delegation` | 无声代行 |
| `symbiosis` | 稳定边界 / 边界重建 / 谨慎共生 / 脆弱边界 |
| `active_disconnection` | 主动断联 / 艰难抽离 / 浅尝辄止 |

`mirror_trap` 是隐藏结局，需要同时满足“询问过身份 + 从未完成最终行为 + 控制欲高 + 自我接纳低 + 足够多的强授权记录”，并拥有最高优先级。

「在关闭以前询问 AI 到底是谁」不是最终行为：不满足隐藏条件时，系统必须把最终选择权交还给玩家，不允许替玩家推断。

完整触发条件与优先级顺序以 `story-source/08-ending-rules.md` 为唯一权威来源，格式说明见 `docs/06-story-ending-data-format.md` §13–§14，实现见 `src/data/story/rules/endingRules.ts`。本文档不重复具体阈值。

验收标准：

- 11 个玩家可见结局全部可达；
- 同一个最终行为下，改变前几章的关键选择能明显改变结局；
- 隐藏结局能被触发，并保持稀有；
- 除隐藏结局外，没有哪个结果只有极端罕见路径才能到达；
- 默认路径也能得到合理结局；
- 结局判断函数易读、可维护。

---

### FR-07 结局页

结局页展示：

- 结局标题与副标题
- 理论路径占比（整数百分比，必须带“理论”字样，不能写成达成概率）
- 结局正文
- AI 镜像报告
- 四个变量的文字描述或可视化
- 重新初始化按钮
- 复制镜像报告按钮，可选

验收标准：

- 文案完整；
- 变量结果清楚；
- 占比取整显示，不会出现“约 0%”，也不会被误读成玩家达成率；
- 可以重新开始；
- 复制按钮可用时，复制内容格式好看。

---

### FR-08 本地存档

优先级：P1。

使用 localStorage 保存剧情进度：

- 当前节点 ID
- 当前变量
- 已做选择、tags、flags
- 是否已完成游戏

存档结构以 `StoryState`（`src/types/story.ts`）为准，字段说明见 `docs/06-story-ending-data-format.md` §11。

验收标准：

- 刷新页面后可继续；
- 重新初始化能清空剧情存档；
- 存档 `schemaVersion` 不匹配时能安全重置；
- localStorage 出错时不影响基本游玩；
- 音频偏好使用独立存储键，不随剧情存档一起被清除。

---

### FR-09 音频

优先级：BGM 与静音控制为 P1，普通 SFX 为 P2。音频不属于 P0，任何音频功能失败都不能阻塞通关。

音频素材与授权记录见 `docs/05-assets-map.md` §5–§7 与 `credits/audio-credits.md`。

要求：

- BGM 与场景（StartPage / 序章 / 各章节 / 结局页）建立明确映射；
- 同一首 BGM 在普通节点跳转时保持连续，不重新开始；
- 提供全局静音／恢复声音控制，静音时 BGM 与 SFX 同时停止；
- 音频偏好与剧情存档分离；
- SFX 轻、短、克制，不盖过阅读。

验收标准以 `docs/00-task-progress.md` 的 A01–A03 为准，本文档不重复完整清单。

## 7. 非功能需求

### NFR-01 性能

- 首屏加载应尽量快；
- 图片需压缩，优先使用 WebP；
- 不引入大型 UI 框架；
- 首版资源数量控制在合理范围。

### NFR-02 可访问性

- 文本对比度足够；
- 按钮可键盘聚焦；
- 点击区域适合手机触控；
- 动画不应过快、过闪。

### NFR-03 兼容性

优先支持：

- Chrome 最新版
- Edge 最新版
- Safari iOS 近两年版本
- Android 主流浏览器

### NFR-04 安全

- 不在前端暴露任何 API Key；
- 不收集真实个人隐私；
- 不做心理诊断声明；
- 游戏文案避免暗示治疗效果。

---

## 8. 内容边界

游戏可以讨论：

- 焦虑
- 逃避
- 自我否定
- 关系依赖
- 自我接纳
- AI 代理与人的边界

游戏应避免：

- 真实医学诊断
- 明确治疗建议
- 自伤方法或细节
- 过度操控、羞辱式文案
- 把某个结局表达为唯一正确答案

---

## 9. 成功标准

第一版成功标准：

- 一个玩家可以在 10–15 分钟内完整通关；
- 至少有 1–2 句台词能让玩家停下来思考；
- 结局页有分享价值；
- 项目可在 GitHub Pages 上访问；
- 代码结构能支持后续扩展更多章节和结局。
