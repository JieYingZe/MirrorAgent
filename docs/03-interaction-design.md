# 《镜中代理》交互设计文档

版本：v0.1  
目标：定义页面流程、用户操作、状态变化、移动端与可访问性规则。

---

## 1. 页面列表

MVP 包含三个核心页面：

1. StartPage：开始页
2. GamePage：剧情游玩页
3. EndingPage：结局报告页

不强制使用路由库。第一版可以通过 `App` 中的 `screen` 状态切换页面。

---

## 2. 整体流程

```txt
打开网页
  ↓
StartPage
  ↓ 点击「开始初始化」
GamePage / prologue
  ↓ 阅读文本
  ↓ 选择回应
GamePage / chapter_1
  ↓
GamePage / chapter_2
  ↓
GamePage / chapter_3
  ↓
GamePage / chapter_4
  ↓
GamePage / chapter_5
  ↓ 最终选择
EndingPage
  ↓
重新初始化 / 复制报告
```

如果存在未完成存档：

```txt
打开网页
  ↓
StartPage 显示「继续实验」和「重新初始化」
  ↓
继续实验 → 回到存档章节
重新初始化 → 清空存档，从序章开始
```

---

## 3. StartPage 交互

### 3.1 页面元素

- 游戏标题：镜中代理 / Mirror Agent
- 副标题：你创造了一个 AI。后来，它开始创造你。
- 简短说明：
  - 一次 10–15 分钟的 AI 心理寓言
  - 建议佩戴耳机或在安静环境体验
- 主按钮：
  - 无存档：开始初始化
  - 有存档：继续实验
- 次按钮：
  - 有存档：重新初始化

### 3.2 状态

| 状态 | 展示 |
|---|---|
| 无存档 | 只显示“开始初始化” |
| 有未完成存档 | 显示“继续实验”和“重新初始化” |
| 已完成游戏 | 可显示“重新初始化”或“查看上次报告” |

第一版可以不实现“查看上次报告”，结局后只保留重新开始。

---

## 4. GamePage 交互

### 4.1 页面布局

桌面端建议：

```txt
┌─────────────────────────────────────────┐
│ 顶部：章节标题 / Mirror Agent 状态       │
├───────────────────────────┬─────────────┤
│ 剧情文本区                 │ AI 状态面板 │
│                           │             │
│ 选项区                     │ 选择记录/变量│
└───────────────────────────┴─────────────┘
```

移动端建议：

```txt
┌──────────────────┐
│ 章节标题          │
│ AI 状态折叠/简版  │
│ 剧情文本          │
│ 选项按钮          │
└──────────────────┘
```

移动端可将 AI 状态面板放在剧情上方或下方，不要占据过多高度。

---

### 4.2 文本展示规则

如果实现打字机效果：

1. 当前段文本逐字显示；
2. 文本显示过程中点击文本区或“继续”：
   - 立即显示完整当前段；
3. 当前段完整显示后点击“继续”：
   - 显示下一段；
4. 当前章节所有文本显示完后：
   - 显示选项；
5. 选项未出现前，禁止提前选择。

如果不实现打字机效果：

- 直接显示当前章节所有段落；
- 选项在段落下方显示；
- 保持阅读节奏即可。

---

### 4.3 选项交互

每个选项展示为一张按钮卡片。

按钮内容：

- 玩家回应文案；
- 可选：简短语气标签，例如“交给 AI”“保留边界”“请求真相”。

第一版建议不要显示变量变化，以保持沉浸感。

点击选项后：

1. 按钮进入短暂 disabled 状态；
2. 应用变量变化；
3. 记录选择历史；
4. 保存本地进度；
5. 进入下一章节；
6. 页面顶部滚动回合适位置。

---

### 4.4 AI 状态面板

面板展示四个状态，但不显示裸数字。

示例：

| 变量 | 低 | 中 | 高 |
|---|---|---|---|
| gentleness | 语气：低保护 | 语气：平衡 | 语气：保护性增强 |
| honesty | 反馈：委婉 | 反馈：校准中 | 反馈：直面模式 |
| control | 权限：工具模式 | 权限：建议模式 | 权限：代理倾向上升 |
| selfAcceptance | 边界：不稳定 | 边界：形成中 | 边界：稳定 |

状态文案应短，像系统日志，不要像心理测试结果。

---

### 4.5 章节切换

章节切换建议：

- 文本区淡出 150–250ms；
- 新章节淡入 250–400ms；
- 不要使用强烈闪烁；
- 第四章“失控日志”可以有轻微异常效果，例如按钮减少、背景偏暗、状态面板出现 warning 标记。

---

## 5. EndingPage 交互

### 5.1 页面元素

- 结局标题
- 结局副标题，可选
- 结局正文
- AI 镜像报告
- 四个变量结果描述
- 选择路径摘要，可选
- 按钮：
  - 复制我的镜像报告
  - 重新初始化

### 5.2 镜像报告格式

复制内容建议：

```txt
《镜中代理 Mirror Agent》

我的结局：共生工具

AI 镜像报告：
你允许我提醒你，但不允许我替你选择。
你允许我指出模式，但不允许我定义你是谁。

状态记录：
- 语气：平衡
- 反馈：直面但可承受
- 权限：工具模式
- 自我边界：稳定

“我创造了一个 AI，后来它开始创造我。”
```

### 5.3 复制交互

- 点击按钮后复制到剪贴板；
- 成功时显示“已复制镜像报告”；
- 失败时显示一个 textarea，让玩家手动复制；
- 不应因为复制失败影响重新开始。

---

## 6. 本地存档交互

### 6.1 保存时机

建议在以下时机保存：

- 开始游戏后；
- 每次选择后；
- 进入新章节后；
- 到达结局后。

### 6.2 存档结构

```ts
type SaveData = {
  version: 1
  currentChapterId: string
  stats: Stats
  choices: ChoiceRecord[]
  finalChoice?: string
  completed: boolean
}
```

### 6.3 清空存档

点击“重新初始化”时：

- 弹出轻量确认，或直接清空；
- 返回序章；
- 变量重置；
- 选择历史清空。

第一版可以不弹窗，但按钮文案要明确。

---

## 7. 错误与边界状态

| 场景 | 处理 |
|---|---|
| 找不到章节 ID | 返回开始页或显示错误提示 |
| story.json 格式错误 | 显示“实验数据损坏” |
| localStorage 不可用 | 继续游戏，但不保存 |
| 图片加载失败 | 使用渐变背景兜底 |
| Clipboard 不可用 | 显示手动复制文本框 |
| 移动端宽度很窄 | 选项全宽排列，状态面板简化 |

---

## 8. 移动端交互规则

- 所有主要按钮高度不低于 44px；
- 选项卡片使用全宽；
- 正文行高保持舒适；
- 不使用 hover 作为唯一反馈；
- 避免页面横向滚动；
- 背景图要加遮罩，保证文字可读；
- 状态面板可以折叠或简化。

---

## 9. 键盘与可访问性

- 按钮使用原生 `<button>`；
- 保留焦点样式；
- 文字对比度足够；
- 动画不应闪烁；
- 如果使用打字机效果，应允许跳过；
- 动态提示如“已复制”可用 `aria-live="polite"`。

---

## 10. 交互优先级

P0：

- 开始游戏
- 阅读剧情
- 选择回应
- 变量变化
- 进入结局
- 重新开始

P1：

- 打字机效果
- AI 状态面板
- 本地存档
- 移动端优化

P2：

- 复制报告
- 选择路径摘要
- 背景图随章节变化
- 轻微音效
