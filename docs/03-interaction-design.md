# 《镜中代理》交互设计文档

版本：v0.1  
目标：定义页面流程、用户操作、状态变化、移动端与可访问性规则。

更新：2026-07-28 完成一次文档一致性整理，与仓库实际结构对齐。

---

## 1. 页面列表

MVP 包含三个核心页面：

1. StartPage：开始页
2. GamePage：剧情游玩页
3. EndingPage：结局报告页

另有两个非核心业务界面：

- StartupGate：启动遮罩，应用级覆盖层，不算第四个核心页面；
- DataErrorPage：剧情数据损坏时的统一出口，见 §9。

不强制使用路由库。第一版可以通过 `App` 中的 `screen` 状态切换页面。

---

## 2. 整体流程

### 2.1 启动流程

```txt
打开网页
  ↓
显示 StartupGate / 启动遮罩
  ↓ 点击「点击进入实验」
尝试解锁音频并播放首页 BGM
  ↓
进入 StartPage
  ↓ 点击「开始初始化」或「继续实验」
进入剧情
```

要点：

- 「点击进入实验」和「开始初始化」是两个独立动作，不合并；
- StartupGate 只负责首次交互与音频解锁，不读写剧情存档；
- 音频解锁或播放失败时仍然进入 StartPage，不阻塞，不弹错误弹窗；
- StartPage 仍然负责新游戏、继续实验和重新初始化。

### 2.2 剧情流程

```txt
StartPage
  ↓ 点击「开始初始化」
GamePage / prologue
  ↓ 阅读文本
  ↓ 选择回应
GamePage / chapter_1
  ↓
GamePage / chapter_2
  ↓
GamePage / chapter_3
  ↓
GamePage / chapter_4
  ↓
GamePage / chapter_5
  ↓ 最终选择
EndingPage
  ↓
重新初始化 / 复制报告
```

如果存在未完成存档：

```txt
StartupGate → StartPage 显示「继续实验」和「重新初始化」
  ↓
继续实验 → 回到存档节点
重新初始化 → 清空剧情存档，从序章开始
```

「重新初始化」只清空剧情存档，不清除音频偏好。

## 3. StartupGate 交互

### 3.1 元素

```txt
MIRROR AGENT

点击进入实验

建议佩戴耳机
```

### 3.2 行为

| 步骤 | 行为 |
|---|---|
| 打开网页 | 显示遮罩，遮罩下方可以已经渲染 StartPage，但不可交互 |
| 点击「点击进入实验」 | 尝试解锁音频上下文并播放首页 BGM |
| 音频成功 | 遮罩淡出，进入 StartPage，BGM 继续 |
| 音频失败或被拒 | 遮罩同样淡出，进入 StartPage，静默降级为无声 |
| 再次访问同一会话 | 遮罩只在页面加载后出现一次，不在页面之间反复出现 |

### 3.3 失败降级

- 浏览器阻止播放：进入 StartPage，两个音频开关仍然可用，玩家可再次尝试开启；
- 音频文件加载失败：不重试到阻塞，不影响任何剧情交互；
- 不因为音频问题显示阻断式弹窗或错误页。

## 4. StartPage 交互

### 4.1 页面元素

- 游戏标题：镜中代理 / Mirror Agent
- 副标题：你创造了一个 AI。后来，它开始创造你。
- 简短说明：
  - 一次 10–15 分钟的 AI 心理寓言
  - 建议佩戴耳机或在安静环境体验
- 主按钮：
  - 无存档：开始初始化
  - 有存档：继续实验
- 次按钮：
  - 有存档：重新初始化

### 4.2 状态

| 状态 | 展示 |
|---|---|
| 无存档 | 只显示“开始初始化” |
| 有未完成存档 | 显示“继续实验”和“重新初始化” |
| 已完成游戏 | 可显示“重新初始化”或“查看上次报告” |

第一版可以不实现“查看上次报告”，结局后只保留重新开始。

## 5. GamePage 交互

### 5.1 页面布局

桌面端建议：

```txt
┌─────────────────────────────────────────┐
│ 顶部：章节标题 / Mirror Agent 状态       │
├───────────────────────────┬─────────────┤
│ 剧情文本区                 │ AI 状态面板 │
│                           │             │
│ 选项区                     │ 选择记录/变量│
└───────────────────────────┴─────────────┘
```

移动端建议：

```txt
┌──────────────────┐
│ 章节标题          │
│ AI 状态折叠/简版  │
│ 剧情文本          │
│ 选项按钮          │
└──────────────────┘
```

移动端可将 AI 状态面板放在剧情上方或下方，不要占据过多高度。

---

### 5.2 文本展示规则

如果实现打字机效果：

1. 当前段文本逐字显示；
2. 文本显示过程中点击文本区或“继续”：
   - 立即显示完整当前段；
3. 当前段完整显示后点击“继续”：
   - 显示下一段；
4. 当前章节所有文本显示完后：
   - 显示选项；
5. 选项未出现前，禁止提前选择。

如果不实现打字机效果：

- 直接显示当前章节所有段落；
- 选项在段落下方显示；
- 保持阅读节奏即可。

---

### 5.3 选项交互

每个选项展示为一张按钮卡片。

按钮内容：

- 玩家回应文案；
- 可选：简短语气标签，例如“交给 AI”“保留边界”“请求真相”。

第一版建议不要显示变量变化，以保持沉浸感。

点击选项后：

1. 按钮进入短暂 disabled 状态；
2. 应用变量变化；
3. 记录选择历史；
4. 保存本地进度；
5. 显示选项专属回应（如有）后进入下一节点；
6. 页面顶部滚动回合适位置。

完整的选择事务顺序见 `docs/06-story-ending-data-format.md` §16.3。

---

### 5.4 AI 状态面板

面板展示四个状态，但不显示裸数字。

示例：

| 变量 | 低 | 中 | 高 |
|---|---|---|---|
| gentleness | 语气：低保护 | 语气：平衡 | 语气：保护性增强 |
| honesty | 反馈：委婉 | 反馈：校准中 | 反馈：直面模式 |
| control | 权限：工具模式 | 权限：建议模式 | 权限：代理倾向上升 |
| selfAcceptance | 边界：不稳定 | 边界：形成中 | 边界：稳定 |

状态文案应短，像系统日志，不要像心理测试结果。

---

### 5.5 章节切换

章节切换建议：

- 文本区淡出 150–250ms；
- 新章节淡入 250–400ms；
- 不要使用强烈闪烁；
- 第四章“失控日志”可以有轻微异常效果，例如按钮减少、背景偏暗、状态面板出现 warning 标记。

## 6. EndingPage 交互

### 6.1 页面元素

- 结局标题
- 结局副标题，可选
- 结局正文
- AI 镜像报告
- 四个变量结果描述
- 选择路径摘要，可选
- 按钮：
  - 复制我的镜像报告
  - 重新初始化

### 6.2 镜像报告格式

复制内容建议：

```txt
《镜中代理 Mirror Agent》

我的结局：共生工具

AI 镜像报告：
你允许我提醒你，但不允许我替你选择。
你允许我指出模式，但不允许我定义你是谁。

状态记录：
- 语气：平衡
- 反馈：直面但可承受
- 权限：工具模式
- 自我边界：稳定

“我创造了一个 AI，后来它开始创造我。”
```

### 6.3 复制交互

- 点击按钮后复制到剪贴板；
- 成功时显示“已复制镜像报告”；
- 失败时显示一个 textarea，让玩家手动复制；
- 不应因为复制失败影响重新开始。

## 7. 本地存档交互

### 7.1 保存时机

建议在以下时机保存：

- 开始游戏后；
- 每次选择后；
- 进入新节点后；
- 到达结局后。

### 7.2 存档结构

剧情存档直接保存 `StoryState`（`src/types/story.ts`），字段说明见 `docs/06-story-ending-data-format.md` §11。本文档不重复字段定义。

要点：

- 进度字段是 `currentNodeId`，不是章节 ID；视觉章节由节点的 `chapterId` 推导；
- 版本字段是 `schemaVersion`，与 `storyManifest.schemaVersion` 保持一致；
- 不把剧情正文写入存档。

### 7.3 音频偏好

音频偏好与剧情存档分开保存，使用独立存储键：

- 保存内容：背景音乐开关、音效开关、音量等级；
- 两个通道分别持久化，切换其中一个不会覆盖另一个；
- 不保存当前播放的曲目、播放进度或待播放的音效队列；
- 「重新初始化」不清除音频偏好；
- 存储不可用时使用默认值（两个通道都有声），不影响游玩；
- 旧版本只有一个静音字段时按「一个关等于两个都关」升级，
  升级过程中不丢失自动播放偏好与音量。

### 7.4 清空存档

点击“重新初始化”时：

- 弹出轻量确认，或直接清空；
- 返回序章；
- 变量重置；
- 选择历史清空；
- 音频偏好保持不变。

第一版可以不弹窗，但按钮文案要明确。

## 8. 音频交互

### 8.1 用户可见控件

- 启动遮罩上的「点击进入实验」：唯一的音频解锁入口；
- **背景音乐开关**与**音效开关**：两个独立控件，在 StartPage、GamePage、EndingPage
  都可访问，位置固定在右上角，不遮挡正文。

两个开关是并列的，没有第三个「全部静音」总开关：三个状态之间需要互相同步，
玩家还要先理解它们的优先级，而两个独立开关已经能表达全部四种组合。

各自的要求：

- 原生 `<button>`，`aria-pressed` 表示「这个通道开着」，
  `aria-label` 与 `title` 说明当前状态与点击后的结果；
- 按钮上有可见的「开／关」文字，状态不只靠图标表达；
- 很窄的屏幕上收掉通道名，只留图标与状态字，完整名称仍在 `aria-label` 与 `title` 里；
- 键盘激活与点击行为一致。

开关自身的声音：

- 关闭音效时**不**播放点击声（否则会变成无音效态里残留的一响）；
- 开启音效后播放一次轻点击作为确认；
- 背景音乐开关两个方向都播放点击声，不拿 BGM 自己的起停当反馈 ——
  关掉背景音乐时如果一点声音都没有，玩家无法确认这次点击是否生效。
  音效通道关着时它自然也不响。

### 8.2 状态

两个通道各自独立，下表的「有声／关闭」只针对该通道：

| 状态 | 行为 |
|---|---|
| 未解锁（遮罩阶段） | 两个通道都不播放任何声音 |
| 已解锁 + 背景音乐开启 | 按当前场景播放 BGM |
| 已解锁 + 背景音乐关闭 | BGM 立即停止；场景切换仍然记录，重新开启后播放当前场景的曲目 |
| 已解锁 + 音效开启 | 交互与场景触发 SFX |
| 已解锁 + 音效关闭 | 立即停止全部短音效并丢弃后续触发；重新开启后不补播关闭期间错过的声音 |
| 只关一个通道 | 另一个通道完全不受影响 |
| 播放被浏览器拒绝 | 视为无声，控件可再次尝试开启 |
| 页面隐藏 | BGM 暂停并在恢复后续播；短音效停止且不补播，不叠加播放 |

两个通道的状态分别持久化，见 §7.3。
BGM 与场景的映射、切换边界见 `docs/05-assets-map.md` §6，本文档不重复曲目清单。

### 8.3 失败降级

- 任何音频失败都只影响声音，不影响剧情推进、选择、存档与结局；
- 不因音频错误显示错误页或阻断式弹窗；
- SFX 缺失时静默跳过，不重试。

## 9. 错误与边界状态

| 场景 | 处理 |
|---|---|
| 找不到节点 ID | 显示“实验数据损坏”页，可返回开始页 |
| 路由目标缺失 / 节点无出口 / 结局定义缺失 | 显示“实验数据损坏”页，控制台输出具体原因 |
| localStorage 不可用 | 继续游戏，但不保存 |
| 图片加载失败 | 使用渐变背景兜底 |
| 音频解锁或加载失败 | 静默降级为无声，继续游玩，见 §8.3 |
| Clipboard 不可用 | 显示手动复制文本框 |
| 移动端宽度很窄 | 选项全宽排列，状态面板简化 |

---

## 10. 移动端交互规则

- 所有主要按钮高度不低于 44px；
- 选项卡片使用全宽；
- 正文行高保持舒适；
- 不使用 hover 作为唯一反馈；
- 避免页面横向滚动；
- 背景图要加遮罩，保证文字可读；
- 状态面板可以折叠或简化。

---

## 11. 键盘与可访问性

- 按钮使用原生 `<button>`；
- 保留焦点样式；
- 文字对比度足够；
- 动画不应闪烁；
- 如果使用打字机效果，应允许跳过；
- 动态提示如“已复制”可用 `aria-live="polite"`。

---

## 12. 交互优先级

P0：

- 开始游戏
- 阅读剧情
- 选择回应
- 变量变化
- 进入结局
- 重新开始

P1：

- 打字机效果
- AI 状态面板
- 本地存档
- 启动遮罩与音频解锁
- BGM 场景映射与切换
- 独立的背景音乐开关与音效开关
- 移动端优化

P2：

- 普通交互音效（SFX）
- 复制报告
- 选择路径摘要
- 背景图随章节变化

音频不属于 P0。任何音频功能失败都必须降级为无声，不能阻塞通关。
