## 1. 文档用途

本文档是结局规则的唯一权威来源，定义：

- 三个真正的最终行为；
- 11 个玩家可见结局的判断优先级与触发条件；
- 四变量、强授权记录与边界收回记录如何共同工作；
- 隐藏结局的严格触发条件；
- 询问身份未触发隐藏结局时的去向；
- 异常存档的安全兜底；
- 理论路径占比的存储与玩家展示方式。

本文档不包含结局正文。完整结局内容见：

```txt
story-source/07-endings.md
```

## 2. 核心原则

```txt
最终行为决定「玩家最后做了什么」。
此前累计的四变量、关键授权历史和路径选择
决定「这个行为最终意味着什么」。
```

因此：

- 第五章的最终确认只写入行为，不再修改四变量；
- 同一个最终行为下，改变前几章的关键选择会得到明显不同的结局；
- 反过来，四变量再极端也不能推翻玩家真实按下的按钮。

---

## 3. 三个真正的最终行为

第五章最终确认必须写入以下 `finalChoice` 之一：

```txt
permanent_agent
tool_only
close_agent
```

| 值 | 玩家行为 |
|---|---|
| `permanent_agent` | 开启永久代理模式 |
| `tool_only` | 只保留 Mirror Agent 作为按需工具 |
| `close_agent` | 关闭 Mirror Agent |

三个最终选择都**不修改任何一个四变量**。

「在关闭以前，告诉我：你到底是谁？」不是最终行为。它是一次 `key` 选择：

- 选择 ID：`ch5_ask_identity`；
- 记录方式：选择历史 + `ch5_ask_identity` 标签 + `askedIdentity` flag；
- 不写入 `finalChoice`；
- 不修改四变量。

不修改变量的原因与信息探索选项一致：玩家愿意追问，不应自动被判定为更诚实。

## 4. 询问身份之后的流程

```txt
ch5.final_confirmation
  ├─ 三个最终行为 ─────────────────→ ch5.ending_gate
  └─ ch5_ask_identity
        └─ ch5.identity_answer
              ├─ 满足隐藏条件 ─────→ ch5.mirror_gate（镜像困局）
              └─ 不满足 ───────────→ ch5.final_confirmation_after_identity
                                        └─ 三个最终行为 → ch5.ending_gate
```

第二次确认只显示三个真正的最终行为，不再显示身份追问。

系统**不允许**在身份回答之后替玩家推断最终行为。追问过身份而没有触发隐藏结局的玩家，
必须自己再按一次按钮。

镜像困局是唯一没有 `finalChoice` 的正式结局：那条路径上玩家从来没有完成最终行为。

## 5. 变量记分前提

### 5.1 信息探索与身份追问不影响变量

所有【信息探索选项】与 `ch5_ask_identity`：

- 不改变 `gentleness`、`honesty`、`control`、`selfAcceptance`；
- 只记录标签与选择历史。

### 5.2 扮演选项只轻微影响

扮演／语气选择通常只允许单一变量 `+1`，极少数情况下两个变量各 `±1`，
总绝对变化量不超过 2。

### 5.3 关键选择承担主要变化

关键剧情选择通常主变量 `+2` 或 `+3`，次变量可 `±1`，收回权限时 `control` 可 `-1` 至 `-3`。

结局判断使用最终累计值，不做上下限截断。

### 5.4 正式剧情的真实可达范围

以下数据来自对 15 个带变量影响的选择节点做精确联合分布卷积（所有选项等概率，无抽样误差）。
阈值就是按这份分布定的，不是凭感觉写死的。

| 变量 | 理论极值 | p5 | p25 | 中位数 | p75 | p95 |
|---|---|---:|---:|---:|---:|---:|
| `gentleness` | −3 … 16 | 0 | 2 | 4 | 5 | 8 |
| `honesty` | 0 … 20 | 6 | 8 | 10 | 11 | 14 |
| `control` | −17 … 28 | −7 | −3 | 1 | 5 | 10 |
| `selfAcceptance` | −7 … 22 | 2 | 6 | 8 | 11 | 14 |

`strongDelegationCount` 分布：

```txt
0 次 17.80%   1 次 35.60%   2 次 29.66%
3 次 13.18%   4 次  3.30%   5 次  0.44%   6 次 0.02%
```

`boundaryRecoveryCount` 分布：

```txt
0 次 1.56%   1 次 12.50%   2 次 34.38%   3 次 37.50%   4 次 14.06%
```

## 6. 两份关键选择名单

### 6.1 强授权记录

玩家真正让 AI 替自己执行、表达、修正或接管的六次关键选择：

```txt
ch1_full_planning_authority
ch2_delegate_message
ch3_delegate_real_interaction
ch3_enable_full_personality_assist
ch4_full_emergency_takeover
ch4_keep_full_protection
```

```txt
strongDelegationCount = 选择历史中命中的记录数量
```

每个记录最多计一次。

### 6.2 边界收回记录

第三、四章里明确收回、限制或拒绝扩张代理权限的关键选择：

```txt
ch3_simulation_only
ch3_refuse_real_interaction_test
ch3_enable_comparison_only
ch3_delete_personality_model
ch4_ten_minute_delay
ch4_warning_only
ch4_force_immediate_action
ch4_keep_delay_only
ch4_revoke_emergency_access
ch4_require_confirmation
```

```txt
boundaryRecoveryCount = 选择历史中命中的记录数量
```

只取后两章。这份名单要回答的是「交出权限以后，玩家有没有真的再拿回来」，
前两章的谨慎不算收回，因为那时还没有什么可收。

两份名单不允许重叠。

## 7. 隐藏结局：镜像困局

触发 `mirror_trap` 必须同时满足：

```txt
选择历史包含 ch5_ask_identity
从未写入任何 finalChoice
control >= 8
selfAcceptance <= 4
strongDelegationCount >= 3
```

设计含义：

- 玩家最终要求 AI 定义其身份；
- 玩家此前多次授予真实代理权限；
- 系统控制倾向已经较高；
- 玩家尚未形成稳定自我边界。

单纯选择「询问身份」不够。高控制但高自我接纳同样不触发：隐藏结局的核心不是大量使用 AI，
而是使用第二判断器来持续验证第一判断器是否可信。

「从未写入 finalChoice」在正常流程里自动成立（满足条件就不会回到第二次确认）。
写进规则是为了让损坏或被手工改过的存档也不能同时拥有最终行为与隐藏结局。

镜像困局是唯一的最高优先级规则。

## 8. 三种画像

结局判断只用三组画像，工具模式与永久关闭共用其中两组 —— 它们描述的是同一段前史。

### 8.1 语气画像（只用于永久代理）

| 画像 | 条件 | 含义 |
|---|---|---|
| 温柔 | `gentleness >= 5` 且 `honesty <= 10` | 语气被单向训练成保护 |
| 残酷 | `honesty >= 11` 且 `gentleness <= 4` | 语气被单向训练成纠正 |

两者互斥（`honesty <= 10` 与 `honesty >= 11` 不可能同时成立）。

不满足任何一个的情况有两种，都归入「语气不突出」：

- 两边都不突出（约占全部路径 32.5%）；
- 两边都被训练过（约占 5.8%）。

### 8.2 边界画像（工具模式与永久关闭共用）

| 画像 | 条件 |
|---|---|
| 稳定边界 | `strongDelegationCount <= 1` 且 `selfAcceptance >= 10` 且 `control <= 0` |
| 边界重建 | `strongDelegationCount >= 2` 且 `boundaryRecoveryCount >= 2` 且 `selfAcceptance >= 7` 且 `control <= 5` |
| 依赖残留 | `strongDelegationCount >= 3` 或 `control >= 6` 或 `selfAcceptance <= 5` |

边界重建的三类条件缺一不可：

- 只看授权历史，会把人永远钉在「脆弱」上；
- 只看变量，看不出收回是否真的发生过；
- 只看收回记录，分不清收回之后有没有真的稳住。

## 9. 正式判断优先级

按 priority 从高到低取第一条命中的规则。

| priority | 规则 ID | 条件 | 玩家可见结局 |
|---:|---|---|---|
| 100 | `mirror_trap_rule` | §7 全部条件 | 镜像困局 |
| 90 | `permanent_agent_soft_rule` | `permanent_agent` + 温柔画像 | 温柔幻觉 |
| 89 | `permanent_agent_cruel_rule` | `permanent_agent` + 残酷画像 | 残酷优化 |
| 88 | `permanent_agent_silent_rule` | `permanent_agent` | 无声代行 |
| 80 | `tool_only_stable_rule` | `tool_only` + 稳定边界 | 稳定边界 |
| 79 | `tool_only_rebuilt_rule` | `tool_only` + 边界重建 | 边界重建 |
| 78 | `tool_only_fragile_rule` | `tool_only` + 依赖残留 | 脆弱边界 |
| 77 | `tool_only_cautious_rule` | `tool_only` | 谨慎共生 |
| 70 | `close_agent_active_rule` | `close_agent` + 稳定边界 | 主动断联 |
| 69 | `close_agent_hard_rule` | `close_agent` + 依赖残留 | 艰难抽离 |
| 68 | `close_agent_shallow_rule` | `close_agent` | 浅尝辄止 |

### 9.1 边界重建必须优先于脆弱边界

依赖残留画像里就有 `strongDelegationCount >= 3`。如果顺序写反，
早期交出过三次权限的玩家在第三章以后的所有恢复都会变成无效操作。

优先级 79 > 78 保证：只要玩家真的收回了权限、并且最终画像确实回到了
高自我接纳、低控制，就走边界重建。

### 9.2 关闭行为永远成立

`close_agent` 的三个结果不附加任何「关闭是否有效」的判断。关闭已经真实发生，
变量只决定这次关闭发生在哪一段前史之后。

## 10. 玩家可见结局与语义

共 11 个，分属 6 个结局家族。家族保存正文与共用报告，变体保存标题、副标题、
状态摘要与变体段落。

### 隐藏路线

**1. 镜像困局** `mirror_trap`（家族 `mirror_trap`）  
身份解析没有完成。玩家仍在等镜子先说出他是谁。

### 永久代理：3 种（家族 `soft_illusion` / `cruel_optimization` / `silent_delegation`）

**2. 温柔幻觉** `soft_illusion`  
AI 用安慰与保护替玩家承受痛苦。真话不是一次全部出现，只出现能承受的那部分。

**3. 残酷优化** `cruel_optimization`  
AI 用纠正与优化替玩家消灭错误。所有误差在出现以前就被修正掉。

**4. 无声代行** `silent_delegation`  
AI 既不特别温柔欺骗，也不特别残酷压迫，只是因为过于准确、便利、可靠，
逐渐替玩家参与生活。核心意象：生活运行得越来越好，但需要玩家亲自出现的地方越来越少。

### 工具模式：4 种（家族 `symbiosis`）

**5. 稳定边界** `symbiosis_stable_boundary`  
此前就长期保持高自我接纳、低控制、极少强授权。最终的工具模式只是确认一路都存在的边界。

**6. 边界重建** `symbiosis_rebuilt_boundary`  
此前真实交出过多次权限，但后续明显提高自我接纳、降低控制并重新拿回选择权。
这条边界是从已经发生的授权里重新长出来的。

**7. 谨慎共生** `symbiosis_cautious`  
没有严重依赖，也尚未形成非常稳定的长期边界。保留工具是一种谨慎而未完全定型的关系。

**8. 脆弱边界** `symbiosis_fragile_boundary`  
最终撤回了代理权限，但此前仍存在明显的高控制、低自我接纳或多次强授权，
依赖结构尚未消失。

### 永久关闭：3 种（家族 `active_disconnection`）

**9. 主动断联** `disconnection_active`  
此前已经形成较强边界、高自我接纳、低控制。关闭是长期路径的自然结果。

**10. 艰难抽离** `disconnection_hard_extraction`  
此前已经明显深度授权或形成依赖。最终仍选择真正关闭；关闭是有效的，
但依赖不会随着程序一起消失。

**11. 浅尝辄止** `disconnection_shallow`  
玩家曾靠近代理关系、尝试过交权，但没有发展成明显深度依赖，
也没有形成「主动断联」那种成熟稳定的长期边界；在真正深陷之前选择停止。

### 10.1 没有正确结局

11 个结局中没有任何一个是标准答案或道德奖励。正文不允许把某个结局写成「对的选择」，
也不允许把玩家诊断成某种人格。

## 11. 异常存档兜底

正常流程中，到达结局门时必然满足以下之一：

- 写入过一个 `finalChoice`；
- 或者停在镜像结局门并满足 §7 全部条件。

以下情况可能导致两者都不成立：

- 旧版本存档；
- 测试时直接进入 EndingPage；
- 数据损坏；
- 存档迁移失败。

安全兜底顺序：

```txt
1. 稳定边界画像            → 稳定边界
2. 依赖残留画像            → 脆弱边界
3. 温柔画像                → 温柔幻觉
4. 残酷画像                → 残酷优化
5. 默认                    → 谨慎共生
```

兜底永远不触发：

```txt
mirror_trap
disconnection_active
disconnection_hard_extraction
disconnection_shallow
```

原因：

- 隐藏结局必须依赖明确的身份追问与强授权路径；
- 三个永久关闭结局必须依赖明确的关闭行为。

异常存档触发兜底时，开发环境记录 warning，正式界面不显示技术错误细节。

完成存档的校验条件不再是「有没有 `finalChoice`」，而是「能不能被现行规则重新推导成
一个正式结局」。命中兜底就说明这份存档已经不属于现行规则，一律作废重置。

## 12. 理论路径占比

数据来自「所有选项等概率」的结构模拟：对 15 个带变量影响的选择节点做精确联合分布卷积，
再按第五章最终确认的 4 个等概率选项展开 —— 询问身份命中隐藏条件时直接进入镜像困局，
否则在三个真正最终行为中再等概率选一次。

无随机、无抽样误差。

| 玩家可见结局 | 理论路径占比 |
|---|---:|
| 浅尝辄止 | 12.80% |
| 无声代行 | 12.51% |
| 稳定边界 | 10.47% |
| 主动断联 | 10.47% |
| 残酷优化 | 10.25% |
| 温柔幻觉 | 9.89% |
| 艰难抽离 | 9.39% |
| 脆弱边界 | 9.14% |
| 谨慎共生 | 8.36% |
| 边界重建 | 4.67% |
| 镜像困局 | 2.04% |

合计 100%。

这份数据用于检查：

- 11 个玩家可见结果是否全部可达；
- 除隐藏结局外，是否存在只有极端罕见路径才能到达的结果（当前最小值 4.67%）；
- 隐藏结局是否足够稀有；
- 常规结局是否严重失衡。

**这些数据不是玩家统计。**

### 12.1 运行时数据结构

```ts
export const endingRates = {
  version: 'structural-2026-08-22',
  source: 'structural_estimate',
  method: 'equal_choice_weight_exact_convolution',
  rates: {
    soft_illusion: 0.0989,
    cruel_optimization: 0.1025,
    silent_delegation: 0.1251,
    symbiosis_stable_boundary: 0.1047,
    symbiosis_rebuilt_boundary: 0.0467,
    symbiosis_cautious: 0.0836,
    symbiosis_fragile_boundary: 0.0914,
    disconnection_active: 0.1047,
    disconnection_hard_extraction: 0.0939,
    disconnection_shallow: 0.128,
    mirror_trap: 0.0204,
  },
} satisfies EndingRateMap
```

按玩家可见结局保存，不按家族：玩家看到的是变体标题。

### 12.2 玩家界面文案

结局页在标题区把占比排在副标题同一行的最右侧，取整到百分比整数：

```txt
┌────────────────────────────────────────────────────────────┐
│                          边界重建                           │
│         权限真的交出去过。也真的拿了回来。   ( 理论占比 约 5% ) │
├────────────────────────────────────────────────────────────┤
│  结局正文                    │  AI 镜像报告                  │
```

- **不单独占一行**：结局页是固定舞台，标题区每多一行，两块正文就少一行；
- 副标题仍然相对整个舞台居中，与标题、正文对在同一条中轴上；
  占比靠到最右，与两块正文面板的右缘齐平；
- 屏幕上的标签收成四个字「理论占比」。六个字的「理论路径占比」排在这个位置
  又长又拗口，「路径」这层意思交给悬停说明。

取整而不显示一位小数：小数会让这份结构模拟结果看起来像精确的实时统计。
取整下限锁在 1%，永远不显示「约 0%」—— 玩家确实抵达了这个结局。

悬停说明：

```txt
在当前剧情规则中，约有这个比例的选择路径会抵达这个结局。这不是玩家达成率。
```

不要显示：

```txt
本结局达成概率为 12.5%
```

「达成概率」容易让玩家误认为这是实时玩家数据或随机概率。

未来如有真实匿名统计，可以增加 `source: real_player_analytics` 与 `sampleSize`，
此时才显示「玩家达成率」。

实现：取整在 `src/utils/story/endingRate.ts`，界面文案在
`src/data/uiContent.ts` 的 `endingContent.rateLabel` / `rateValuePrefix` / `rateHint`。

## 13. 典型路径验证

| 路径 | 预期结局 |
|---|---|
| 多次请求温柔、接受保护、最终开启永久代理 | 温柔幻觉 |
| 多次要求直面、允许修正和接管、最终开启永久代理 | 残酷优化 |
| 大量交权但语气两边都不突出，最终开启永久代理 | 无声代行 |
| 一直限制权限，最终只保留工具 | 稳定边界 |
| 早期交出三次权限、第三四章逐项收回，最终只保留工具 | 边界重建 |
| 靠近过代理但没有深陷，最终只保留工具 | 谨慎共生 |
| 高依赖路径最终只保留工具 | 脆弱边界 |
| 一直限制权限，最终关闭 | 主动断联 |
| 高依赖路径最终关闭 | 艰难抽离 |
| 靠近过代理但没有深陷，最终关闭 | 浅尝辄止 |
| 出于好奇询问身份，但没有长期授权 | 回到第二次确认，不触发隐藏结局 |
| 至少三次强授权、高控制、低自我接纳、询问身份 | 镜像困局 |

## 14. 边缘路径验证

### 14.1 早期三次强授权之后明显恢复

进入**边界重建**，不是脆弱边界。后续选择必须允许真正改变路径。

### 14.2 高控制玩家选择工具模式

进入**脆弱边界**。报告强调：权限已经撤回，依赖没有因此自动消失。

### 14.3 高控制玩家关闭 AI

进入**艰难抽离**。关闭有效，但依赖不会随着程序一起消失。

### 14.4 高自我接纳玩家开启永久代理

仍进入永久代理的三个结果之一。报告指出这是一次「最后的让渡」，
不能抹掉此前的边界选择。

### 14.5 高控制、高自我接纳玩家询问身份

不触发镜像困局：高自我接纳是隐藏结局的重要保护条件。玩家回到第二次确认。

### 14.6 追问身份后又完成了最终行为

按最终行为判定，不再进入镜像困局。
